# مراجعي (Maraje3) — البرومت المقسم لـ Replit Agent

## طريقة الاستخدام
1. ابعت **القسم صفر (القواعد العامة)** مرة واحدة في أول رسالة، بعدها أي مرحلة تبعتها لازم يتكرر معاها سطر: "طبّق القواعد العامة اللي فوق".
2. ابعت **مرحلة واحدة بس في المرة**. بعد ما يخلص، راجع تقريره قبل ما تبعت اللي بعدها.
3. المراحل اللي فيها علامة 🔧 محتاجة منك حاجة يدوية (مفاتيح/حسابات) — موضحة في القسم الأخير.

## القسم صفر — القواعد العامة (ينطبق على كل المراحل)

```
أنت بتطوّر تطبيق "مراجعي" — مكتبة موارد للطلبة الجامعيين (ملفات + بنك أسئلة خفيف) بالعربية.

الستاك الحالي (متغيّرهوش):
- pnpm monorepo. تطبيق الموبايل: artifacts/maraje3 (Expo Router, React Native). السيرفر: artifacts/api-server (Express 5). قاعدة البيانات: lib/db (Drizzle + PostgreSQL). عقد الـ API: lib/api-spec (OpenAPI) ← Orval يولّد lib/api-zod و lib/api-client-react.
- أي تغيير في الـ API يتم بتعديل الـ OpenAPI spec أولًا ثم تشغيل: pnpm --filter @workspace/api-spec run codegen — مفيش كتابة hooks أو Zod schemas يدويًا.
- تغيير السكيما: lib/db/src/schema ثم pnpm --filter @workspace/db run push.

قواعد ملزمة:
1. الواجهة عربية RTL بخط Cairo وبنفس الـ theme الحالي. أي نص جديد بالعربية أولًا (والإنجليزي حيث الحقول ثنائية اللغة موجودة أصلًا).
2. ممنوع اختلاق محتوى. الشارة "تجريبي" على أي محتوى demo تفضل زي ما هي.
3. ممنوع إضافة اشتراكات (subscription). نموذج الربح: Free + Ads + Premium شراء لمرة واحدة فقط (المرحلة 7).
4. ممنوع scraping أو سحب محتوى من أي منصة تانية.
5. أي محتوى AI-generated لازم يعدي على مراجعة أدمن قبل النشر. ممنوع نشر تلقائي.
6. التصفح والتنزيل يفضلوا بدون تسجيل دخول دايمًا. تسجيل الدخول لحظة الرفع فقط (والإجراءات اللي بتحتاج هوية ثابتة).
7. أي سر (مفاتيح، توكنز) من environment variables فقط. ممنوع hardcode. لو محتاج قيمة مني، حط placeholder واضح في .env.example واذكره في التقرير.
8. متكسرش الموجود: التطبيق الحالي (الكتالوج، التنزيل، الحفظ، الأوفلاين، الأدمن) لازم يفضل شغال بعد كل مرحلة.
9. نهاية كل مرحلة، شغّل pnpm run typecheck وصلّح أي أخطاء، وابعت تقرير فيه: (أ) الملفات الجديدة/المعدّلة، (ب) أي migration اتعمل، (ج) متغيرات البيئة الجديدة المطلوبة، (د) إيه اللي اتنفّذ فعلًا وإيه اللي اتأجّل أو مش قادر تتحقق منه (ماتقولش "تم" على حاجة ما اختبرتهاش)، (هـ) خطوات يدوية مطلوبة مني.
10. متنتقلش للمرحلة اللي بعدها من نفسك. اقف بعد التقرير.
```

## المرحلة 0 — تنظيف وتأمين (أولوية قبل أي حاجة)

```
طبّق القواعد العامة. المرحلة 0: تأمين وتنظيف.

1) Rate limiting على السيرفر (express-rate-limit):
   - على كل مسارات /api/catalog/admin/*: أقصى 5 محاولات فاشلة (401) لكل IP كل 15 دقيقة، بعدها 429 برسالة عربية. المحاولات الناجحة ماتتحسبش.
   - حد عام معقول على باقي الـ API (مثلًا 120 طلب/دقيقة/IP).
   - فعّل app.set("trust proxy", ...) بشكل صحيح عشان الـ IP الحقيقي يتقرأ خلف البروكسي.
2) CORS: بدل cors() المفتوح، اقرأ allowlist من env اسمه CORS_ORIGINS (قيم مفصولة بفاصلة). لو فاضي في development اسمح بالكل، في production ارفض أي origin مش في القايمة (تطبيق الموبايل الأصلي مش بيبعت Origin فمتكسرهوش).
3) أضف helmet بإعدادات افتراضية آمنة، وحدّ لحجم json body (مثلًا 100kb).
4) توكن الأدمن: اتأكد إن MARAJE3_ADMIN_TOKEN لو أقل من 24 حرف السيرفر يرفض يشتغل في production ويطبع تحذير واضح.
5) شاشة الأدمن: شيل رابطها الظاهر من الرئيسية. خليها route موجود بس مفيش زرار ظاهر ليه (الوصول بضغطة مطوّلة 5 ثواني على شعار التطبيق في شاشة "المزيد" أو ما يعادلها). متحذفش admin.tsx دلوقتي.
6) تنظيف: احذف artifacts/mockup-sandbox، وأي dist أو .expo متتبّعين في git، وحدّث .gitignore. املا replit.md فعليًا (اسم المشروع، وصف سطر واحد، خريطة الملفات، قرارات معمارية 3-5 نقاط، أوامر التشغيل).
7) أضف .env.example بكل المتغيرات المطلوبة حاليًا.
```

## المرحلة 1 — الأداء والتجربة الأكاديمية (اختيار "كليتي" + بيانات الامتحان)

```
طبّق القواعد العامة. المرحلة 1: التوسّع + "كليتي وفرقتي" + بيانات الامتحان.

A) تغيير السكيما (materials):
   - professorName text nullable
   - examYear integer nullable (مثلًا 2024)
   - examType enum: midterm | final | quiz | sheet | other (nullable)
   - appearedInExam boolean default false ("طلع في الامتحان فعلًا" — يتحدد بواسطة الأدمن حاليًا)
   - searchText text not null default '' : نص مُطبّع (نفس دالة normalizeArabic الموجودة) يحتوي عنوان+وصف+اسم المادة+الدكتور+الكلية، يتحدث تلقائيًا عند create/update عبر الأدمن. اعمل backfill للصفوف الموجودة.
   - فهرس على searchText (pg_trgm GIN لو متاح، وإلا btree مناسب) وفهارس على subjectId و publicationStatus.
   عدّل OpenAPI + شاشة الأدمن (حقول جديدة) + عرض المادة.

B) إعادة هيكلة الـ API (من غير ما تكسر القديم فورًا):
   - GET /catalog/tree : الهرمية فقط (جامعات/كليات/فرق/فصول/مواد) بدون المواد، مع ETag/Cache-Control قصير.
   - GET /materials : pagination بـ cursor أو page/limit (الافتراضي 20، أقصى 50)، فلاتر: universityId, facultyId, academicYearId, semesterId, subjectId, category, examType, examYear, professorName, q. البحث يتم في قاعدة البيانات على searchText (بعد تطبيع q بنفس الدالة)، مش في ذاكرة السيرفر. الترتيب: الأحدث أولًا، مع خيار الأكثر تنزيلًا لاحقًا.
   - احتفظ بـ /catalog و /catalog/search القديمين مؤقتًا لكن علّمهم deprecated في الـ spec، وحوّل التطبيق يستخدم الجديد بالكامل.
   - حدّث الكاش الأوفلاين في التطبيق ليتعامل مع tree + الصفحات.

C) "كليتي وفرقتي" (الأهم UX):
   - أول فتح للتطبيق: شاشة onboarding بسيطة (3 اختيارات: جامعة ← كلية ← فرقة، والفصل اختياري) تتحفظ في AsyncStorage.
   - الرئيسية تعرض مواد فصل/فرقة المستخدم مباشرة + أحدث ملفات كليته. زرار "تغيير كليتي" في الإعدادات. زرار "استكشاف كل الكليات" يفضل موجود للتصفح الحر.
   - البحث يبدأ مقيّد بكلية المستخدم مع خيار تحويله لبحث شامل.
   - فلاتر في شاشة المادة/البحث: نوع الامتحان، السنة، الدكتور (chips)، وشارة "طلع في الامتحان" على الملفات.

D) عندما تخلص: اعمل seed واضح (is_demo=true) بأمثلة تغطي الحقول الجديدة فقط لأغراض الاختبار، بشارة تجريبي.
```

## المرحلة 2 — الهوية (Google Sign-In عند الرفع فقط) 🔧

```
طبّق القواعد العامة. المرحلة 2: حسابات المساهمين.

الفلسفة: التصفح والتنزيل بدون حساب. الحساب لازم فقط لـ: رفع ملف، طلب ملف، زرار شكر (لو اخترنا ربطه بالحساب)، وبروفايل المساهم.

1) جدول users: id (uuid), googleSub (unique), displayName, photoUrl, facultyId nullable, role enum (student|admin) default student, status enum (active|suspended) default active, uploadSuspendedUntil timestamp nullable, strikes integer default 0, hideIdentity boolean default false, createdAt.
2) تسجيل الدخول: في التطبيق استخدم Google Sign-In (expo-auth-session أو @react-native-google-signin حسب الأنسب لـ Expo، واذكر السبب). التطبيق يبعت Google ID token لـ POST /auth/google، السيرفر يتحقق منه (google-auth-library) مقابل GOOGLE_CLIENT_IDS (env، قيم متعددة: android/ios/web)، ينشئ/يحدّث المستخدم، ويرجّع session JWT موقّع بـ SESSION_SECRET (env) بصلاحية 30 يوم + refresh بسيط.
3) middleware requireUser للمسارات المحمية. التوكن في Authorization: Bearer. رمز الأدمن القديم (MARAJE3_ADMIN_TOKEN) يفضل شغال كما هو للإدارة — متدمجش النظامين دلوقتي.
4) شاشات: زرار "تسجيل الدخول" يظهر فقط عند محاولة إجراء محمي (مش في أول التطبيق). شاشة بروفايل بسيطة: الصورة، الاسم، الكلية، خيار "إخفاء اسمي وصورتي من الملفات التي رفعتها" (hideIdentity)، زرار تسجيل الخروج، وزرار "حذف حسابي" (يحذف/يُخفي هوية المستخدم ويفك ارتباط ملفاته باسمه — الملفات الموافق عليها تفضل لكن بدون هوية).
5) materials: أضف uploaderId (nullable، FK لـ users). حقل contributor النصي القديم يفضل للمحتوى اللي الأدمن بيدخله يدويًا. العرض: لو uploaderId موجود وhideIdentity=false اعرض صورة+اسم المساهم + كليته؛ غير كده "مساهم مجهول" أو contributor النصي.
6) لا تخزّن أي بيانات زيادة عن الاسم/الصورة/googleSub.
```

## المرحلة 3 — الرفع من الطلبة + المراجعة + البلاغات 🔧

```
طبّق القواعد العامة. المرحلة 3: رفع الملفات مع مراجعة وإدارة محتوى (شرط أساسي لمتجر Google Play للمحتوى من المستخدمين).

1) التخزين: اعمل storage adapter (interface واحد: createUploadUrl / getDownloadUrl / delete) بتنفيذين: (أ) S3-compatible (Cloudflare R2) مضبوط بـ env: STORAGE_ENDPOINT, STORAGE_BUCKET, STORAGE_ACCESS_KEY, STORAGE_SECRET_KEY, STORAGE_PUBLIC_BASE (ب) تنفيذ بديل لو Replit Object Storage متاح. الاختيار بـ STORAGE_DRIVER. الرفع من التطبيق عبر presigned URL مباشرة (السيرفر مايستلمش الملف نفسه).
2) قيود الرفع (تتحقق منها على السيرفر مش بس التطبيق): PDF وصور (jpg/png/webp) فقط، أقصى 25MB، فحص magic bytes بعد الرفع، حساب sha256 وrفض أي ملف مكرر (يرجّع للمستخدم "الملف ده موجود بالفعل" مع رابطه). حد رفع: 10 ملفات/يوم/مستخدم (قابل للضبط).
3) تدفق الرفع في التطبيق: زرار "ارفع ملف" ← (تسجيل دخول لو لسه) ← اختيار الملف ← اختيار المادة (مقيّد بكليته افتراضيًا) ← العنوان، النوع، الدكتور، السنة، نوع الامتحان ← إقرار إلزامي (checkbox): "أؤكد أن لي الحق في مشاركة هذا الملف وأنه ليس منسوخًا من كتاب أو مصدر محمي" ← إرسال. الملف يتسجل بحالة pending.
4) publicationStatus يتوسّع: draft | pending | published | rejected، مع rejectionReason نصي. الطالب يشوف حالة رفعاته في بروفايله (قيد المراجعة/منشور/مرفوض + السبب). ملفات pending/rejected ما بتظهرش للعامة أبدًا.
5) قائمة مراجعة في شاشة/صفحة الأدمن: عرض الـ pending مع معاينة الملف، أزرار (نشر / رفض مع سبب / تعديل البيانات ثم نشر). عند الرفض يزيد strikes للمستخدم؛ عند 3 رفضات متتالية: uploadSuspendedUntil = الآن + 7 أيام (قابل للضبط).
6) البلاغات: جدول reports (id, targetType material|profile|request, targetId, reporterUserId nullable, reporterDeviceId, reason enum: copyright|inappropriate|wrong_info|spam|other, details, status open|resolved|dismissed). زرار "إبلاغ" على كل ملف وعلى كل بروفايل مساهم. POST /reports (rate limited). قائمة بلاغات للأدمن مع إجراءات: إخفاء الملف فورًا (unpublish)، تجاهل البلاغ، إيقاف الرفع للمستخدم.
7) سحب المحتوى بسبب حقوق الملكية: صفحة ويب ثابتة بسيطة من السيرفر /takedown فيها بريد/نموذج للتبليغ، + في الأدمن زرار "سحب بسبب حقوق ملكية" يخفي الملف ويسجل السبب والتاريخ.
8) حقل authorized الحالي يفضل: الملف المرفوع من طالب authorized=true تلقائيًا بناءً على الإقرار، لكن الأدمن لازم يقدر يغيّره.
```

## المرحلة 4 — التقدير والتحفيز

```
طبّق القواعد العامة. المرحلة 4: نظام التقدير (المساهم "المنقذ").

1) أرقام الاستخدام: جدول material_stats أو أعمدة على materials: downloadCount, thanksCount. تنزيل يُحسب مرة واحدة لكل (جهاز/مستخدم، ملف) في اليوم. اعمل anonymous install id يتولد في أول فتح ويتخزن في AsyncStorage ويتبعت في header (X-Device-Id) لمنع التكرار بدون تسجيل.
2) زرار "شكرًا 👍" تحت كل ملف: جدول thanks (materialId, deviceId, userId nullable) بقيد unique على (materialId, deviceId). مرة واحدة لكل جهاز لكل ملف. يظهر العداد للجميع، وللمساهم في بروفايله.
3) الألقاب (محسوبة وقت العرض من الأرقام، مش محفوظة)، والعتبات في ملف constants واحد قابل للتعديل:
   - "مساهم جديد": أول ملف منشور.
   - "منقذ الدفعة": 10 ملفات منشورة أو 500 تنزيل إجمالي.
   - "أسطورة الكلية": أعلى مساهم (بالتنزيلات) في كليته خلال الفصل الحالي.
   اللقب مبني على الملفات المنشورة فقط، مش المرفوضة أو المعلّقة.
4) بروفايل مساهم عام (من الضغط على اسمه): الصورة، الاسم، الكلية، اللقب، عدد الملفات، إجمالي التنزيلات والشكر، قايمة ملفاته المنشورة. (يحترم hideIdentity.)
5) لوحة الشرف: لكل كلية على حدة (مش عامة) — أعلى 10 مساهمين للفصل الحالي + "كل الأوقات". GET /leaderboard?facultyId=. تظهر في تبويب أو قسم في الرئيسية.
6) سطر الشرف تحت كل ملف: "رفعه: [الاسم] · [الكلية]" بشارة اللقب لو موجود.
7) مكافأة: حقل users.premiumGranted boolean، يتفعّل تلقائيًا لما المستخدم يحقق 5 ملفات منشورة وإجمالي تنزيلاتها ≥ 100 (عتبات قابلة للضبط). لسه مفيش Premium فعلي (المرحلة 7)، بس جهّز الحقل واعرض للمستخدم "فتحت Premium مجانًا" كإشعار داخل التطبيق.
8) حماية من التلاعب: الألقاب والعدادات تتأثر فقط بتنزيلات من أجهزة مختلفة (deviceId مميّز)، ورفعات المستخدم نفسه لملفاته ماتتحسبش.
```

## المرحلة 5 — لوحة "مطلوب"

```
طبّق القواعد العامة. المرحلة 5: طلبات الملفات.

1) جدول material_requests: id, facultyId, subjectId nullable, titleAr (وصف الطلب، مثلًا "ملخص مادة X للدكتور Y"), requesterUserId nullable, requesterDeviceId, status open|fulfilled|closed, fulfilledByMaterialId nullable, meTooCount, createdAt. جدول request_meToo (requestId, deviceId) unique.
2) إنشاء طلب يتطلب تسجيل دخول (لمنع السبام) وحد 3 طلبات/يوم. زرار "أنا كمان" (me too) بدون تسجيل يزوّد العداد (مرة لكل جهاز).
3) شاشة "مطلوب" (تبويب أو قسم): طلبات كلية المستخدم مرتبة بعدد "أنا كمان" ثم الأحدث، مع فلتر بالمادة. كل طلب فيه زرار "عندي الملف ده" ← يفتح تدفق الرفع (المرحلة 3) مربوط بالطلب مسبقًا.
4) لما ملف مرتبط بطلب يتنشر: الطلب يتحول fulfilled ويتربط بالملف، ويظهر للمساهم "لبّيت طلب" وتتضاف شارة صغيرة في بروفايله (عدّاد "طلبات لبّاها").
5) الأدمن يقدر يقفل/يحذف طلب، والمستخدمين يقدروا يبلّغوا عن طلب (reports.targetType=request).
```

## المرحلة 6 — الرجوع اليومي والنمو (مشاركة + عداد امتحان + بوت تليجرام) 🔧

```
طبّق القواعد العامة. المرحلة 6: الاحتفاظ بالمستخدمين والنمو عبر جروبات تليجرام (شريك مش منافس).

A) عداد الامتحان (محلي بالكامل، بدون سيرفر):
   - المستخدم يضيف امتحان: المادة (من مواد كليته) + التاريخ + نوع الامتحان. يتخزن في AsyncStorage.
   - شاشة/كارت في الرئيسية: "باقي X يوم على امتحان [المادة]" مع زرار يفتح ملفات المادة، ومؤشر "حفظت N ملف من المادة دي".
   - إشعارات محلية (expo-notifications) قبل الامتحان بـ 7 و 3 و 1 يوم و يوم الامتحان صباحًا. طلب صلاحية الإشعارات عند إضافة أول امتحان مش عند فتح التطبيق.
B) روابط المشاركة:
   - زرار "مشاركة" على كل ملف يولّد رابط https://<PUBLIC_BASE_URL>/m/<id> (من env).
   - السيرفر يخدم صفحة ويب خفيفة على /m/:id فيها OpenGraph (عنوان الملف، المادة، الكلية، اسم المساهم لو مسموح) وزرار "افتح في التطبيق" (deep link) وبديل رابط المتجر. اضبط Expo linking/deep links لفتح material/[id] مباشرة. الصفحة لا تعرض الملف نفسه، بس معاينة.
   - نص المشاركة الافتراضي بالعربية يحتوي الرابط.
C) بوت تليجرام (حزمة منفصلة artifacts/telegram-bot، باستخدام grammY) 🔧:
   - يشتغل بـ TELEGRAM_BOT_TOKEN و BOT_API_SECRET (env). يتواصل مع السيرفر عبر endpoint داخلي POST /internal/submissions محمي بـ BOT_API_SECRET.
   - التدفق: أي شخص يبعت ملف (PDF/صورة) للبوت في خاص أو يعمله forward أو يرد عليه في جروب البوت فيه: البوت يسأله بأزرار inline: الكلية ← الفرقة ← المادة ← النوع، ثم يسجّل الملف كـ submission بحالة pending (source=telegram, telegramUsername اختياري) في نفس قائمة مراجعة المرحلة 3. نفس قيود الحجم/النوع/الـ hash/الحد اليومي.
   - يرد للمرسل: "وصلنا ملفك وهيتراجع قريبًا ✅" ولما يتنشر يبعتله إشعار (لو لسه في المحادثة).
   - أمر /ربط يربط حساب تليجرام بحساب التطبيق (كود مؤقت) عشان الرفعات تتنسب لهويته وتتحسب في ألقابه.
   - الأدمن في التطبيق يشوف مصدر كل submission (تطبيق/تليجرام).
D) أداة "رفع بالجملة" للأدمن (لأدمن الجروبات والـ seed): شاشة/endpoint يرفع عدة ملفات دفعة واحدة لمادة واحدة مع تحديد "مصدر: جروب [اسم]" يظهر كاعتراف بالمصدر على الملفات.
```

## المرحلة 7 — وضع المذاكرة الخفيف + الربح

```
طبّق القواعد العامة. المرحلة 7: بطاقات المراجعة (Flashcards) + الإعلانات + Premium مرة واحدة.

A) Flashcards (نسخة خفيفة، من غير SM-2 دلوقتي):
   - جداول: decks (subjectId, titleAr, createdByUserId, status pending|published) و cards (deckId, questionAr, answerAr, optional options json للـ MCQ/صح-غلط، explanationAr nullable).
   - إدخال: من الأدمن أولًا (شاشة إنشاء/لصق بالجملة بصيغة سطر لكل بطاقة "سؤال | إجابة"). المساهمين يقدروا يقترحوا decks بنفس مسار المراجعة (pending ← أدمن).
   - للطالب: شاشة مراجعة بطاقة بطاقة (اقلب البطاقة، "عرفتها / لسه"). التقدم محلي على الجهاز فقط (AsyncStorage)، مع وضع "راجع اللي ما عرفتهوش". عداد جلسات يومي بسيط.
   - صمّم الجداول بحيث نقدر نضيف SM-2 لاحقًا (حقول easiness/interval/dueAt محلية).
B) الإعلانات (react-native-google-mobile-ads) 🔧 — تحتاج development build مش Expo Go، اذكر ده في التقرير:
   - Banner في قوائم الملفات/نتائج البحث (بين العناصر أو أسفل القائمة). ممنوع داخل شاشة عرض الملف أو أثناء المراجعة.
   - Rewarded: بعد 3 تنزيلات مجانية في اليوم، التنزيل الرابع يتطلب مشاهدة إعلان مكافأة (أو Premium). لو الإعلان مش متاح يتمنح التنزيل (fallback).
   - Interstitial: ممنوع نهائيًا.
   - IDs من env/config مع test IDs في development. اطلب الموافقة (UMP consent) حسب المنطقة.
C) Premium شراء لمرة واحدة (react-native-iap أو بديل مناسب) 🔧:
   - منتج واحد non-consumable (سعر قابل للضبط من Play Console، المقترح 15-25 جنيه) يفتح: بدون إعلانات + تنزيل غير محدود.
   - التحقق من الشراء على السيرفر (Google Play Developer API) وتخزين entitlement على حساب المستخدم، مع Restore purchases. المستخدم المجهول (بدون حساب) يعتمد على التحقق المحلي من Play Billing.
   - users.premiumGranted (من المرحلة 4) يفتح نفس المميزات مجانًا.
   - شاشة Premium بسيطة وصريحة (إيه اللي بتاخده، سعر مرة واحدة).
D) ممنوع أي اشتراك متكرر.
```

## المرحلة 8 — الامتثال لمتجر Google Play

```
طبّق القواعد العامة. المرحلة 8: الامتثال لسياسات Google Play للمحتوى من المستخدمين.

1) سياسة الخصوصية: صفحة ويب على السيرفر /privacy بالعربية والإنجليزي توضح: البيانات المجمعة (حساب Google: الاسم/الصورة، deviceId، الملفات المرفوعة، بيانات الاستخدام)، الإعلانات (AdMob)، التخزين، مشاركة الاسم والصورة علنًا مع الملفات (ومعها خيار الإخفاء)، حقوق المستخدم في الحذف.
2) شروط الاستخدام وسياسة المحتوى /terms: ممنوع رفع محتوى مسروق/محمي/مسيء، حق الأدمن في الإزالة، التبليغ، الإيقاف.
3) حذف الحساب: داخل التطبيق (موجود من المرحلة 2) + صفحة ويب /delete-account فيها تعليمات وخيار طلب حذف عبر البريد — Play بتشترط الاتنين لو التطبيق فيه حسابات.
4) آليات الإشراف موجودة ومتاحة بسهولة: زرار إبلاغ على الملفات/البروفايلات/الطلبات (المرحلة 3 و5)، حظر/تعليق المستخدمين المخالفين، وصفحة /takedown لحقوق الملكية.
5) شاشة "عن التطبيق" داخل التطبيق: الإصدار، روابط الخصوصية والشروط والتبليغ، وتواصل.
6) أنشئ مجلد docs/ في الريبو فيه: data-safety.md (إجابات Play Console مستخلصة من الكود الفعلي مش تخمين)، store-listing.md (اسم، وصف قصير ≤80 وطويل بالعربي والإنجليزي)، و play-checklist.md بحالة كل بند (جاهز/ناقص/يدوي).
7) تأكد إن الأذونات الأندرويد المطلوبة فعلًا بس (إنترنت، إشعارات، تخزين حسب الحاجة)، واتحقق من package/applicationId موحّد ومناسب (com.angelosonsy.maraje3 مثلًا) وإن إعدادات الـ build للتوقيع جاهزة للـ release.
```
